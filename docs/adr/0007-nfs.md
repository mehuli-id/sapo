# ADR 0007: Shared folder lewat NFS

- **Status:** Diterima
- **Tanggal:** 2026-10-24

## Konteks

Komputer Linux dan Mac sering lebih nyaman memasang folder NAS lewat NFS. NFS dengan `sec=sys` tidak meminta password: server memercayai UID dan grup yang dikirim klien, jadi siapa pun yang menjadi root di komputernya sendiri bisa mengaku sebagai pengguna mana pun. Izin folder Sapo (ADR 0006) berupa ACL per akun dan grup, dan harus tetap berlaku sama lewat NFS. Kerberos (`sec=krb5`) belum tersedia di Sapo.

## Keputusan

- **Ekspor NFS diatur per folder** dari aplikasi Shared Folder: daftar alamat klien dan satu pengguna Sapo. Disimpan di `shares.json` bersama izin folder, dan diterapkan lewat `shares.apply` yang sama.
- **Semua akses dari klien berlaku sebagai pengguna itu** (`all_squash`, `anonuid`/`anongid` = UID akun dan grup utama `sapo-users`). UID yang dikirim klien tidak pernah dipercaya, termasuk root di klien. Grup tambahan dari klien dibuang oleh kernel.
  - Izin NFS sama dengan izin efektif pengguna itu di folder, menurut aturan ACL POSIX: izin langsung pengguna bila ada, bila tidak izin terluas dari grupnya. `sapo-api` menghitungnya (baca & tulis → `rw`, baca saja → `ro`, tanpa izin → tidak diekspor). Karena grup tambahan dibuang, `sapod` menambahkan entri ACL untuk akun itu sendiri di sistem berkas (bukan di Samba).
  - Pengguna nonaktif, dihapus, gagal disinkronkan, atau bentrok dengan akun sistem tidak diekspor. Menghapus pengguna mematikan ekspor folder yang memakainya.
  - `sapod` hanya memetakan klien ke akun buatannya sendiri (tercatat di catatan akun, di rentang ID `agent.accounts.id_min`–`id_max`, bergrup utama Sapo), jadi tidak pernah ke root atau akun sistem lain, walau `sapo-api` disusupi.
- **Klien hanya alamat IP atau jaringan lokal** dalam bentuk kanonis, paling banyak 32 per folder: di dalam 10/8, 172.16/12, 192.168/16, 100.64/10 (VPN), atau fc00::/7. Nama host tidak diterima (bisa dipalsukan lewat DNS), alamat publik juga tidak.
- **File ekspor ditulis utuh oleh `sapod`** (`/etc/exports.d/sapo.exports`) dari templat tetap: satu baris per folder, path folder yang sudah diperiksa (dataset bertanda `sapo:share`, ADR 0006), opsi tetap `sec=sys,ro|rw,sync,all_squash,secure,no_subtree_check,mp`. Lalu `exportfs -ra`. Ekspor diterapkan dulu dan selalu, walau Samba gagal.
  - Bila gagal, **semua ekspor Sapo dicabut** dan server NFS dimatikan (gagal-tertutup); file lama tidak dipulihkan karena bisa memberi akses yang baru dicabut.
  - `mp`: folder yang belum terpasang (misalnya gagal dipasang saat boot) tidak diekspor sebagai direktori biasa di sistem berkas pool. Karena itu `no_subtree_check` aman: setiap ekspor selalu satu sistem berkas (dataset) utuh.
  - `secure`: klien harus memakai port istimewa (di macOS: opsi `resvport`).
- **Hanya NFS versi 4 lewat TCP** (`/etc/nfs.conf.d/sapo.conf` dari paket): satu port (2049), tanpa NFSv2/v3 dan tanpa UDP. rpcbind di-mask saat paket pertama dipasang; uji asap memastikan rpcbind dan mountd tidak menjawab dari jaringan.
- **Server NFS hanya berjalan (dan menyala saat boot) selama ada folder yang diekspor**: `sapod` menjalankan `systemctl enable --now` / `disable --now` untuk `agent.shares.nfs_service`. Ekspor di `/etc/exports` buatan admin ikut berhenti bila Sapo tidak mengekspor apa pun; NFS di Sapo diatur lewat panel.
- **Mengatur NFS butuh password admin** dan tercatat di log audit, sama dengan mengubah izin folder.
- **Menghapus folder atau pool mencabut ekspornya dulu**, sebelum dilepas dan dihapus. Bila menghapus folder gagal setelah itu, folder baru diekspor lagi pada sinkronisasi berikutnya (gagal-tertutup).

## Alasan

- Memetakan semua akses ke satu akun membuat NFS tidak bergantung pada UID di komputer klien, jadi tidak ada pengguna yang bisa mengaku sebagai pengguna lain, dan izinnya bisa dijelaskan di panel dengan satu kalimat.
- Izin dari data yang sama (izin folder + keanggotaan grup) berarti mencabut izin di panel juga mencabut akses NFS.

## Alternatif

- **Memercayai UID klien** (`root_squash` saja, seperti NFS biasa): UID klien harus disamakan dengan UID Sapo, dan root di klien mana pun di jaringan yang diizinkan bisa membaca data semua pengguna. Ditolak.
- **NFS dengan Kerberos**: aman per pengguna, tetapi butuh KDC dan pengaturan klien; bisa ditambahkan nanti.
- **NFSv3**: dibutuhkan klien NFS Windows, tetapi butuh rpcbind dan mountd di jaringan. Pengguna Windows memakai SMB.

## Konsekuensi

- Semua orang di alamat klien yang diizinkan berbagi satu identitas di folder itu; untuk akses per orang, pakai SMB.
- File yang dibuat lewat NFS dimiliki akun NFS dan mewarisi ACL folder, jadi tetap terbuka bagi pengguna lain sesuai izin folder.
- Klien NFS harus root (`sudo mount`) karena port istimewa.
